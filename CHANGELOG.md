# Changelog

Notable changes, newest first. Undated entries predate November 2026. Design decisions are recorded in [docs/adr/](./docs/adr/) and measurement results in [eval/RESULTS.md](./eval/RESULTS.md).

- 2026-11-12: a controlled tag is optional, as in the blog's lint: a post gets one only when one names its topic (a post with none shows no related reading, which beats wrong related reading). The taxonomy calls no longer ask again for a missing one, and the publish check no longer rejects a post without one; such a post's PR carries a note to add one if one names its topic.
- 2026-11-12: a review-and-cleanup pass.
  - The guide sandbox check (`tech_guide.run_examples`) blames a post only for misusing the product's API: a wrong call signature of a name imported from the product, an import of a product name or submodule that does not exist, a product module's missing attribute, or an SDK's own parameter or service-name validation. Any other failure makes the check partial, shown as a PR note.
  - The sandbox blames only a failure the post's own code raised: one raised inside another installed package that uses the product (a plugin built for another version) is a partial-check note. A product name called through its module (`serve.deployment(...)`) or imported under another name counts as the product's. Option values of `pip`/`uv pip` (`--torch-backend cpu`) are no requirements, and a quoted requirement keeps its specifier.
  - A block marked `# excerpt` is never judged by the static code check.
  - A survey drops figures that arXiv lists but does not serve before reading, so no section describes a figure that is not shown.
  - A version after a name ("Llama 3.1", "Python 3.12") is no longer cut as an unsourced number when the sources' non-number evidence writes it after a name. A benchmark score still is: a pair whose number any number evidence states is never exempt.
  - Headings: one claim-heading rule and one no-TL;DR-retelling rule for both paper engines. The sentence-heading check keeps no noun lists: a heading of more than one word ending in "~다" is a sentence, a lone word is left to the section review. The evidence engine's writers get the shared heading-structure rules.
  - Data: name lookups of the pinned HTTP transport run on threads of their own, so their 15 s deadline never counts a wait for a busy worker thread. arXiv retries only transient failures. arXiv figures have their own pace. A transient document-parse failure is retried before falling back to text only.
  - Operations: the hourly cost alarm fires at twice the largest per-run ceiling (was a fixed $50). `JobResult.input_tokens` is documented as including cache tokens.
  - A post shows each figure once: a repeat of an image already shown is dropped when a post's images are checked.
  - The paper and survey readers record a setup value (training steps, learning rate, batch or data size) as a finding with its quote, not as a result. Reader versions: survey 10, paper 4, so the next run reads its papers again once.
  - Evaluation: `eval/sets/baseline.yaml` marks dev and confirm items. `eval/JUDGE.md` describes the pairwise blind protocol, and `eval/compare.py` applies it: only confirm items decide, each item needs three sessions, and a preference the blind mapping does not resolve is an error. Measurement history moved to `eval/RESULTS.md`. Evaluation posts are no longer committed.
- 2026-11-11: a survey's comparison table no longer shows a figure a paper only cites as its result: the survey reader records only a paper's own measured results as numbers (a qualitative paper may have none; the ask for a missing number says so), and numbers of related-work, background and preliminaries sections stay in their section. The survey reader version is 9, so the next survey run reads its papers again once.
- 2026-11-11: `tech_guide.run_examples` (default off) runs a guide's Python examples in reading order in an Amazon Bedrock AgentCore Code Interpreter sandbox without AWS credentials (Batch: the stack's custom interpreter with public network, so the docs' packages install; local: `tech_guide.code_interpreter_id` or AWS's system interpreter, which installs nothing). A block of a usage or operations section that fails because of its own code is fixed and run again; one still failing, a sandbox that could not run, or a run stopped by a missing credential, network or service is a PR note. The stack adds the interpreter (no cost while idle) and the job role may start, invoke and stop sessions on it only.
- 2026-11-10: `status` of a running Batch job, or one that died without a result, shows its `progress` (current stage, model calls, estimated cost so far, last report time, Batch attempt), written by the worker to `<s3_prefix>/progress/<job_id>.json` at most every 30 seconds.
- 2026-11-10: `--engine sections|evidence` (review, summarize) and `--max-cost-usd` (review, summarize, guide, survey write) override the configuration for one run, so a Batch job no longer needs a redeploy to try another engine or ceiling. The sections engine's review checks its TL;DR and closing claims against the paper (one fix, kept when it has fewer problems) and caps background sections at 15% of its length budget.
- 2026-11-10: stage checkpoints are kept under a version of the check code (a hash of the domain package and the engine modules), so a deploy that changes checks, repairs or edit rules never resumes from a stage the old code made; the reading cache is unaffected. The first run of each input after such a deploy recomputes its stages once.
- 2026-11-09: the evidence engines' outline checkpoints include the version of the outline checks asked again for (key targets, sentence titles, source sections a review leaves out): runs resumed after this upgrade recompute their outline and later stages once. A survey comparison table shows only result cells that state a number in a noun phrase; other numbers stay in their section.
- 2026-11-09: `cancel <job-id>` stops a remote job, `status` reports its CloudWatch `log_group` and `log_stream` once it started, and the guide code check flags a call that does not match the post's own definition of a function or class (missing required arguments, unknown keywords).
- 2026-11-09: `max_cost_usd` stops reviews and summaries on either engine; a failed run's result lists `blocking` problems on their own, `publish --resolved` clears them after a fix, and a Batch result no longer points to container paths. Expired or missing AWS credentials and denied access stop figure and code analysis instead of leaving a degraded post; a failed code index keeps the codebase summary. Invalid arguments and config files are reported in one line naming each bad key (and the file).
- 2026-11-09: reviews and summaries have two peer engines (ADR 0004): `explanation.engine` / `summary.engine` choose `sections` (default) or `evidence`, and neither is slated for removal. The sections engine moved from `scholar_lens/legacy` to `scholar_lens/sections_engine`; commands, configuration and outputs are unchanged.
- 2026-11-08: the code is layered (docs/engine.md 5.1): `domain` (pure), `application` (the engine, one use case per command, ports), `adapters` (AWS, Bedrock, web, scholarly indexes, documents, GitHub, PyPI), `legacy` (the sections engine) and the entrypoints (`cli.py`, `entrypoints/`, the composition root `bootstrap.py`); `scholar_lens/src` is gone and import-linter enforces the layers. Tests are split into `tests/unit` and `tests/integration`. Commands, job JSON and outputs are unchanged.
- 2026-11-08: the evidence engines save every stage (key targets, outline, sections, whole-post result, TL;DR, final text) under a hash of its inputs, and a rerun with the same inputs resumes from them, a Batch retry included; `--fresh` recomputes. `publish <markdown_path|s3_uri>` checks a saved or rejected (edited) post again and opens its PR on the run's branch; every run saves its publish request next to the post for it.
- 2026-11-08: guides are checked against the product's own code: the packages the official docs install are read from PyPI (never run) and indexed, the guide's import paths, names and keyword arguments must exist there, and the definitions a section uses decide defaults, signatures and return values in its checks. Each guide section owns the features it teaches (`topics`), evidence for another SDK language leaves the outline, a scope or SDK qualifier must stay with its fact, and a guide defaults to at most 11 sections and 25,000–45,000 characters.
- 2026-11-07: runs check before any model call that the category types fit the blog, that a PR run has `GITHUB_TOKEN` and that `--search-query` has a search provider. The claim check also removes sentences about the post's own sources; a fix's notes never reach the post; a paper's repeated facts and figures go to one section; guide Python blocks in the usage and operations sections are checked in reading order for code that does not parse or uses names no earlier block defines (REPL and notebook cells and code after `import *` are not judged), and checked again after the fixes; a claim check or review the models cannot answer leaves the draft and a run note. Data sources: per-host HTTP connections, project-scoped official pages on shared hosts (GitHub, Hugging Face), title matching that rejects "…Is Not…" or "…: A Survey" and accepts a dropped short name, venue names kept as written for workshops and regional chapters. `costs --billed` filters on `resources.project_name`; Batch traces to LangSmith only with `SCHOLAR_LENS_BATCH_TRACING=true`.
- 2026-11-06: guides and surveys are written only by the evidence engines: the guide `sections` engine and the survey `cards` engine are gone, with their config keys `tech_guide.engine`, `writer_enable_thinking`, `evaluator_enable_thinking`, `verify_grounding`, `min_quality_score`, `max_revision_attempts`, `max_total_tokens` and `survey.engine`, `card_source_chars`, `min_quality_score`, `max_revision_attempts`, `verify_grounding`, `write_max_total_tokens`. Delete them from your `config.yaml`, or loading fails with `extra_forbidden`. The cost ceilings `tech_guide.max_cost_usd` and `survey.write_max_cost_usd` bound a run. Reviews and summaries keep both engines (`explanation.engine`, `summary.engine`).
- Surveys are written by the evidence-ledger engine. Reading agents record each fact with the paper's verbatim words, checked in code; the outline gives each fact to one section and the comparison table owns its numbers; sections are checked number by number and claim by claim, and only sentences contradicting their evidence are cut. On the evaluation set (three judge runs each) both surveys score at least the previous engine's median on every criterion, with far fewer repeated numbers and twice the figures ([results](./eval/RESULTS.md)). Bedrock's content filter, which stopped attack-heavy sections mid-sentence, is retried and then handed to the reading model.
- Math: a bare `|` inside a probability or policy call (`p(y|x)`, `\pi_\theta(a|s)`) becomes `\mid` (it was `\vert` in inline math and left alone in display math), and `\minimize`, `\maximize`, `\argmin`, `\argmax`, which MathJax does not define, become `\operatorname*{…}`. A survey description still over 160 characters after its repair is cut at its last sentence end within 120–160 characters.
- Survey venues name where a paper was published: an OpenAlex venue comes from its first conference or journal location (not a repository such as Zenodo, an institute such as CISPA, or a book series such as "Lecture notes in computer science"), and venue names from OpenAlex, Semantic Scholar and the plan's reference list are normalized (`domain/venues.py`: NeurIPS, ICML, ICLR, ACL, EMNLP, Findings of ACL, TMLR, NDSS and others by their short names; an all-lower-case catalogue title in title case). Semantic Scholar 429s without `Retry-After` are retried up to four times with doubling waits (5, 10, 20, 40 s) instead of once. Every model call is recorded (`llm_usage` log line, `JobResult.usage` by stage and model, per-stage CloudWatch metrics, the three costliest stages in the SNS notification) and `scholar-lens costs` reports spend from the result manifests; Bedrock calls go through per-kind application inference profiles tagged `Kind` so Cost Explorer splits Bedrock spend by kind (`cdk deploy --all`).
- Links a docs page or search result carried as relative paths (`../_images/x.svg`) are resolved against that page's URL when a search result's Markdown is read, and the publish step reduces any link the blog cannot follow (not http(s), site-relative, an anchor or mailto, or with empty text) to its text, or to its image for a linked image. A Ray Serve guide failed the blog's htmlproofer on such a link.
- Dependencies follow the October 2026 updates (arxiv 4.0, requests 2.34, PyMuPDF 1.28, aws-cdk-lib 2.273, GitHub Actions on Node 24). PDF code imports `pymupdf` (the `fitz` alias now prints a deprecation warning to stdout, which broke the worker's one-JSON-object output). The compute environment no longer lists `optimal` explicitly: CDK adds it, and the template had it twice. Redeploy to pick up the new image.
- After the targeted fix, a guide or survey section is re-scored once with the same evaluator call (one extra evaluator call per section that needed a fix): the fixed draft is kept only when it ranks no lower than the pre-fix draft (passes, publishable, factual issues, score, then wording issues and rule slips), else the pre-fix draft is kept. The below-the-bar PR note now reports the re-scored score and remaining issues, and says whether the fix was applied, reverted or rejected; past the soft token budget the re-score was skipped (the guide and survey token budgets were removed on 2026-11-06; a cost ceiling bounds those runs). Before publishing, the blog's post conventions are read again; when the blog changed them during the run (e.g. a topic cover), the post is validated against the current ones, its `cover` is recomputed from its categories, and the PR notes "Blog conventions changed during the run". A failed re-read keeps the conventions the run started with.
- Summaries use plain `##` headings without emoji: research background, proposed method, implementation, experimental results, significance and limits (in Korean 연구 배경, 제안 방법, 구현 방식, 실험 결과, 의의와 한계). The Batch launch template encrypts the root volume (`/dev/xvda`, 30 GiB gp3) with the AWS-managed EBS key, and the compute environment pins the template's latest version, so a template change reaches the environment on `cdk deploy --all` as an in-place infrastructure update; redeploy to pick it up.
- The publish checks follow the blog lint of PR #99: a fence inside a blockquote (`` > ``` ``) is code, so its `<tag>` lines, `$$` and lightbox examples are no longer flagged and its `$$` no longer turns `use_math` on; it closes on a quoted closing marker (a `` > ``` `` line inside a bare ```` ```markdown ```` block stays part of that example) or, left open, is an unclosed-fence error where its blockquote ends at a blank line. A table separator needs one dash a cell, as on the blog; `<ellipse>` and `<marker>` are no longer allowed HTML. A description must be longer than the page title, which is now the `seo_title` on every post that sets one (the blog's `<title>`), not only on Korean paper posts.
- Tags: a post gets one controlled tag by default (the paper's, guide's or survey's own topic) and a second only when the method, whole sections or whole lineages are about it; an existing tag's spelling is reused only when it names the paper's own contribution. Guides now get a generated `description` from the taxonomy call, checked by the publisher's description rules with one repair round (a description that still fails is a PR note; one with markup or no longer than the title is dropped and the blog derives it). A summary with publish blockers left gets one targeted fix call, kept only when it removes blockers without new ones or lost structure. The Korean style block turns a 다-ending glued to a colon before a list (`셋입니다:`) into a period. The survey evaluator blocks a passage that re-explains what an earlier section already explained. A guide leaves out a command, flag or default that only an older docs version gives. Paper cards were cached under card schema 4: a card's limitations were the paper's own and a result setting written as a sentence was a card problem (superseded: the cards engine was removed on 2026-11-06; surveys now cache evidence).
- Paper figures written as HTML (`<img src>`, a hand-written figure or lightbox) are copied into the blog like Markdown images, and an `<a href>` lightbox link to a copied image points at the copy, so `href` stays equal to `src`.
- Every page, image and PDF is fetched over HTTPS: an `http://` request or redirect is upgraded to `https://` on the same host and path, since the Batch security group allows only port 443 egress (a site without HTTPS fails to fetch). arXiv HTML pages and PDF downloads go through the shared arXiv rate limiter, and a server `Retry-After` holds arXiv requests for at most 60 seconds. A failed guide web search (429, 5xx, timeout) is not retried; the count is a run note. Semantic Scholar batch requests carry 100 ids (was 500) to stay well inside the 30-second timeout. A guide's product name comes only from the command names its docs show, never from the site's host name. The Batch compute environment moves to the latest ECS-optimized AMI on each `cdk deploy --all`.
- Regenerating a post the blog already has keeps its file name, URL, image names, `date` and topic (`categories`), whatever title or topic the model picks this run: the post is found by its slug, else as the post an earlier run of the same branch (review/summary arXiv id, guide input URLs, survey plan topic) published in a merged pull request, and it is validated under that final file name. The blog sync no longer renames a post; a published copy the run did not see stops the pull request with an error, and a branch-only older copy of the post under another title is removed from an open pull request. Both need `resources.github.author_email`.
- The survey write budget `survey.write_max_total_tokens` was raised to 4.5M tokens (from 3M; a 22-paper run used 2.7M). Superseded: the key was removed on 2026-11-06 and `survey.write_max_cost_usd` bounds the write stage. After the revision, a guide or survey section's blocking issues that are still open get one targeted fix call that rewrites only the sentences they name; the fix is dropped when it adds a rule slip or loses the draft's structure (a heading, image or citation key, an equation or table, or over a quarter of the prose), and the PR note lists the issues.
- Generated posts follow the blog lint's newest rules as it applies them: an empty first table header cell is an error (name the row kind, such as "구분" or "모델"), and a first row with a blank first cell is a second header row unless one of its cells is a plain number (`85.2`, not `85.2±0.3`); translationese and a sentence ending glued to a colon are publish-blocking errors with the blog's exemptions (headings, quotations, table rows, image alt text, code, the reference list); `paper_author` may not contain "et al" in any case; an arXiv `paper_doi` carries no version and a DOI URL or `doi:` prefix is dropped; tags keep a last "In"/"On" capitalized (`Opt-In`) and may not start with "." or "+"; math and `use_math` are checked on the lines the blog lint reads, including indented code blocks and fences inside blockquotes. `http://` and protocol-relative link and image targets are rewritten to `https://` at publish time, and any left fail validation, as the blog's htmlproofer fails them. The MathJax macro warning reads the blog's `math.defined_macros`.
- `paper_doi` is checked like the blog lint does: a paper post's `paper_doi` must be a bare DOI (`10.<registrant>/<suffix>`, no spaces, `?` or `#`), and `paper_author` or `paper_doi` on a survey or guide is an error.
- With `SEMANTIC_SCHOLAR_API_KEY` set, citation summaries also take abstracts from Semantic Scholar (last in the lookup chain) and link the paper's arXiv DOI or DOI rather than its Semantic Scholar page; survey plans add its citation counts, venues and references (its `arXiv.org` venue never replaces a known venue). A key a provider rejects (401/403) skips that provider for the rest of the run, and a 5xx is retried once.
- Korean prose reads less like a translation: every writer, editor, fact-checker and survey card gets one shared Korean style block (`domain/prompts/rules.py::KOREAN_STYLE`: noun frames, particle calques, actor-hiding and double passives, English default verbs, formulaic sentences, the "입니다" register, a table cell a noun phrase or an "입니다" sentence, one form per table), the review checker and the guide and survey evaluators quote unnatural sentences with a rewrite and block only a sentence whose grammar or agent changes its meaning and a plain 다-form prose sentence (`<wording_issues>` in the guide and survey evaluators), and the writing-rule check flags double passives (`되어진`), a closed set of "에 있어" calques (`에 있어서는`, `에 있어서의`, `학습함에 있어`; a bare "에 있어서" is left to the model checks) and a sentence ending glued to a colon (`같습니다:`). Paper cards were then cached under card schema 3 with the translation guideline in the cache variant (superseded by the 2026-11-06 removal of the cards engine).
- `survey plan --reference URL` (repeatable; `reference_urls` on survey_plan requests) is back, and now used: the plan stage reads each reference for the scope call and adds the papers it is or links to as candidates (a tie-break after topic evidence in the rank, `[REFERENCED by N]` in the shortlist); the plan stores them as `references[]` (`schema_version` 3; version 1 and 2 plans still load); the write stage uses the reference articles as explanatory material in the sections that frame the field and lists them as further reading after `### References`. Redeploy before using it with `--remote`.
- New `survey write --plan <file>` (kind `survey_write`): turns a (possibly edited) plan into a `Paper Surveys` post with cached paper cards, an outline, guide-style section writing and checks, deterministic timeline and comparison tables, the papers' figures and author-year citations. It needs the blog's post conventions to list the `Paper Surveys` type (`resources.github.survey_category`). The guide's evaluate-and-revise loop and grounding retry are now shared functions (`section_loop.revise_section`, `checked_grounding`), with unchanged behaviour. Redeploy before using it with `--remote`.
- New `survey plan "<topic>"` (kind `survey_plan`): finds a topic's major papers and saves an editable plan (`plan_path`, `s3_uri`). Without `SEMANTIC_SCHOLAR_API_KEY` citation counts are OpenAlex's, which undercount arXiv-era ML papers, and few citation links are known. Redeploy before using it with `--remote`.
- After upgrading, redeploy (`cdk deploy --all`) before using `--remote`: the Batch image runs the code of the last deploy, and an older worker rejects a request with a field it does not know (such as `--reference`).
- Guides go deeper and broader: usage, how the internals work and why, and how to fit the tool into a larger system. An outline-level section plan assigns each concept to one owning section, the evaluator's blocking issues (factual errors, contradictions, unsupported flags or defaults) force a revision, and `tech_guide.max_revision_attempts` defaulted to one revision (superseded: the guide `sections` engine and its keys were removed on 2026-11-06). A run cost more than before.
- `guide --reference URL` (repeatable) adds reference material (papers, design docs, deep-dive posts) next to the docs URLs, and a guide can be built from references alone. Docs URLs may now come before or after the options.
- New guide defaults: `tech_guide.fetch_top_results` is now 12 (was 4) and `tech_guide.max_sections` caps the outline. A `config.yaml` copied from an older template keeps its old values; edit them to pick up the new defaults.
- Paper posts carry `paper_doi` front matter (the arXiv DOI for arXiv papers, else the paper's DOI when known); the blog looks the citation count up on Semantic Scholar.
- Citation lookups: OpenAlex follows Crossref in the chain (keyless use allows about 100 searches per day per IP; set the optional `OPENALEX_API_KEY` to raise it), Crossref picks the matching record among its top five hits, and Semantic Scholar is queried only when `SEMANTIC_SCHOLAR_API_KEY` is set.
- Removed config keys: `resources.github.default_cover_image`, `resources.github.cover_images`, `paper.table_of_contents_model_id`, `paper.output_fixing_model_id`, `citations.citation_analysis_model_id`, `explanation.paper_analysis_model_id` and `explanation.paper_enrichment_model_id`. Edit your `config.yaml` and delete them, or loading fails with `extra_forbidden`.
- Removed entry points and stack: the Slack bot and its Lambdas (`Dockerfile.lambda`, the `SLACK_*` secrets), `scholar_lens/main.py`, `scholar_lens/tech_guide_main.py`, `scripts/run_batch.py` and the spot compute environment. Use the `scholar-lens` CLI (locally or with `--remote`); Batch runs on one on-demand compute environment.
- Only the paper's own figures are copied into the blog (arXiv HTML figures, figures recovered from the arXiv source, figures cropped from the PDF). Any other image (docs sites, blogs, reference material) stays a link to its source and is listed on the PR checklist as `remote image not localized`. A paper figure that cannot be stored blocks the post; the run result's `markdown_path` and `s3_uri` then point to the rejected draft.
- ar5iv is never used: an ar5iv link fails validation, and an arXiv figure that comes back as ar5iv's "NO IMAGE AVAILABLE" placeholder is taken from the paper's arXiv source (`/e-print`).
- A `glightbox` link must open its own image (`href` equal to the inner `src`), or the post is rejected.
- Paper posts carry a generated `description` (120-160 characters of plain text that open with the model or method name and are unique on the blog). Its numbers are checked against the TL;DR and the abstract, and the TL;DR's numbers against the paper; a mismatch feeds the review's repair attempt or becomes a PR note, and only a description that is not unique on the blog blocks the post. Scaled and combined Korean numbers are compared as quantities (`12만 8천` matches `128K`); a lone `N만` counts as sourced when the source has either N or N×10⁴, since `만` may also be the particle "only".
- Rerunning a published post lists on the PR the hand edits made to it or its images since it was generated, so they can be carried over. Merge the tool's pull requests with a merge commit: after a squash or rebase merge the generated commit is not on the base branch, so every commit to the post is listed.
- Reference and source lists are `[title](url)` lines, one per URL; a guide's sources use the fetched page titles.
- Guide section lengths count prose only: code, table rows and images are excluded.
- One terminology rule in every prompt: the translation guideline's rendering wins for each term it lists (guides now receive the guideline too); other terms are translated where natural, with the English in parentheses at first use. The lint flags any 하다/되다 form glued to an English word (`prefill하면서`, `swap-in되어`).
