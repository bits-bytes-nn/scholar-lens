# 0003. 리뷰·요약은 근거 장부 엔진이 가린 비교에서 이길 때까지 이전 엔진을 기본으로 둔다

- 상태: 일부 대체(ADR 0004). 기본값 결정은 유효하고, 삭제 기준은 0004가 대체합니다.
- 관련: `docs/engine.md` 1장(코드·아키텍처), 8장 E9, `explanation.engine`, `summary.engine`

## 배경

가이드와 서베이는 근거 장부 엔진만 씁니다. 리뷰와 요약은 이전 엔진(`sections`, 당시 `scholar_lens/legacy/`, 지금 `scholar_lens/sections_engine/`)이 기본이고 근거 장부 엔진(`evidence`)은 선택 사항입니다. 설정 일부는 두 엔진 중 한쪽에서만 동작합니다.

## 결정

- 리뷰·요약의 기본 엔진은 `sections`로 둡니다.
- 근거 장부 엔진이 ADR 0002의 절차로 확인용 항목에서 이전 엔진 이상이라고 판정될 때 기본값을 바꾸고, `legacy/`와 전용 설정을 지웁니다.

## 현재 상태

- 가린 비교 두 차례(`eval/RESULTS.md` 8절)에서 근거 장부 엔진은 논문 9쌍 모두 졌습니다. 첫 차례는 읽기 단계가 핵심 대상만 기록한 탓이었고, 이를 고친 두 번째 차례에서도 글이 짧고 충분성(방법 절, 정리, 주요 결과)과 일부 사실에서 졌습니다.
- 따라서 기본값은 바꾸지 않습니다. 근거 장부 엔진의 논문 경로를 다시 평가하려면 최소 길이 보장 이후 버전으로, 확인용 항목을 포함해 같은 절차를 따릅니다.
- 최소 길이 보장 이후 버전(8fc5f9a)으로 다시 평가한 세 번째 차례(`eval/RESULTS.md` 9절, 2026-11-09)에서도 5쌍 모두 졌습니다. 기본값은 그대로입니다.

## 결과

- 두 엔진을 함께 유지하는 비용(설정, 테스트, 문서)이 남습니다.
- 삭제 기준이 평가 결과로 정해져 있어, 엔진 교체가 품질 후퇴로 이어지지 않습니다.

## 의존성

- `langchain-community`는 유지 관리가 끝나 가고 있어 이전 엔진에서 쓰지 않습니다. 임베딩은 `langchain_aws.BedrockEmbeddings`를 씁니다. 이 클래스는 엔드포인트의 botocore 오류를 그대로 다시 던지므로 공통 재시도 정책(`adapters/retry.py`)이 다른 Bedrock 호출과 같은 기준으로 분류합니다.
- 코드 색인은 FAISS 대신 `langchain_core`의 `InMemoryVectorStore`(코사인 유사도, 메모리 안 전수 비교)를 씁니다. 색인은 실행마다 메모리에서만 만들고 저장하지 않으며, 저장소 파일·청크 수 상한 안에서는 FAISS의 평면 색인과 같은 전수 비교라 성능 차이가 작습니다. 결과의 `similarity`는 이제 L2 거리가 아니라 코사인 유사도(클수록 가까움)입니다.
- `langchain-community`와 `faiss-cpu`는 의존성에서 지웠습니다. 메모리 안 색인의 코사인 유사도가 쓰는 `numpy`는 직접 의존성으로 선언합니다.
