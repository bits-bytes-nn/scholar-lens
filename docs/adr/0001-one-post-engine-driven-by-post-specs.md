# 0001. 하나의 PostEngine을 PostSpec으로 움직인다

- 상태: 채택
- 관련: `docs/engine.md` 2장, 4.0절, 8장 E1

## 배경

리뷰·요약, 가이드, 서베이의 근거 장부 엔진이 같은 흐름(근거 읽기, 개요와 수리, 잘못된 근거 제거, 절 작성·검사·수정, 글 전체 검토, TL;DR, 마무리)을 따로 구현했습니다(`application/*_engine.py` 약 2,100줄). 검사 장치가 엔진마다 다르게 붙어, 한 종류에서 고친 결함이 다른 종류에는 남았습니다.

## 결정

- 흐름은 `application/post_engine.py`의 `PostEngine` 하나가 소유합니다.
- 글 종류별 차이는 `domain/specs/`의 `PostSpec` 데이터(절 종류, 고정 제목, 근거 정책, 길이, 실행 대상 절, 포함 여부, 글 전체 단계, 프롬프트, `Limits`)와 이름이 붙은 작은 훅으로만 넣습니다.
- 엔진 코드에는 글 종류 분기, 제품·논문·호스트 이름, 함수 안의 숫자를 두지 않습니다. 숫자는 근거를 적은 `Limits`나 설정 값입니다.

## 결과

- 검증기 묶음, 편집 트랜잭션, 판정 캐시, Checkpoint가 모든 종류에 같이 적용됩니다.
- 새 종류는 명세와 훅으로 추가하고, 명세 4종의 개요 규칙은 계약 테스트로 고정합니다.
- 종류별 엔진 파일은 명세를 읽고 프롬프트를 조립하는 얇은 계층으로 남습니다. 그 안에서도 종류 분기를 늘리지 않습니다.
