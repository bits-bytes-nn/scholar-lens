## TL;DR

LoRA는 사전 학습된 가중치를 고정하고, 적응 과정의 가중치 변화량만 작은 두 행렬의 곱으로 학습하는 미세조정 기법입니다. 가중치 변화가 낮은 "내재 랭크"를 가진다는 가설을 바탕으로 합니다. GPT-3 175B를 Adam으로 파인튜닝하는 경우와 비교하면 학습 파라미터는 10,000배, GPU 메모리는 3배 줄어들고, 품질은 RoBERTa, DeBERTa, GPT-2, GPT-3에서 파인튜닝과 같거나 더 낫습니다. 추론 지연도 추가되지 않습니다.

## 연구 배경

모든 파라미터를 다시 학습하는 전체 파인튜닝은 과제마다 원본과 같은 크기의 모델을 하나씩 만들어 냅니다. GPT-3 175B 규모에서는 이런 인스턴스를 과제별로 저장하고 배포하는 비용이 감당하기 어려워집니다. 퓨 샷 학습으로 대신하기도 어렵습니다. 부록 실험에서 GPT-3의 MNLI-m 정확도는 퓨 샷이 40.6%, 파인튜닝이 89.5%였습니다.

기존의 효율적 적응 기법은 두 갈래이고, 각각 약점이 있습니다. 어댑터 계열은 블록 사이에 층을 순차적으로 끼워 넣기 때문에 계산을 병렬화할 수 없습니다. GPT-2 medium에서 배치 1, 시퀀스 길이 128로 측정하면 지연이 19.8ms에서 $$\text{Adapter}^{\text{L}}$$은 23.9ms(+20.7%), $$\text{Adapter}^{\text{H}}$$는 25.8ms(+30.3%)로 늘어납니다. 프리픽스 튜닝 계열은 최적화가 까다롭습니다. 학습 파라미터를 늘려도 성능이 단조롭게 오르지 않고, 특수 토큰이 과제에 쓸 수 있는 시퀀스 길이를 차지합니다.

## 제안 방법

출발점은 과매개변수화된 모델이 실제로는 낮은 내재 차원(intrinsic dimension) 위에 놓여 있다는 선행 관찰입니다. 저자들은 여기서 착안해 적응 중의 가중치 변화량 $$\Delta W$$도 랭크가 낮을 것이라고 가정합니다. 사전 학습 가중치 $$W_0 \in \mathbb{R}^{d\times k}$$는 그대로 두고, 변화량을 $$\Delta W = BA$$로 분해해 $$B\in\mathbb{R}^{d\times r}$$와 $$A\in\mathbb{R}^{r\times k}$$만 학습합니다. 랭크는 $$r \ll \min(d,k)$$입니다. 순전파는 다음과 같습니다.

$$
h = W_0 x + \frac{\alpha}{r} BAx
$$

![입력 x가 고정된 사전 학습 가중치 W와 저랭크 경로 A, B로 동시에 들어가 출력이 합쳐지는 LoRA 구조도](/assets/images/lora-low-rank-adaptation-of-large-language-models-summary-1.png)

구조도에서 볼 부분은 두 경로가 직렬이 아니라 병렬로 놓여 있고, 출력이 좌표별로 더해진다는 점입니다. $$A$$는 가우시안 무작위값으로, $$B$$는 0으로 초기화합니다. 그래서 학습을 시작하는 시점에는 $$\Delta W = 0$$이고, 모델이 사전 학습 모델과 똑같이 출발합니다. 배율 $$\alpha/r$$는 $$r$$을 바꿀 때 하이퍼파라미터를 다시 조정할 필요를 줄이려고 넣었습니다. Adam에서는 $$\alpha$$를 바꾸는 것이 학습률을 바꾸는 것과 거의 같아서, 처음 시도한 $$r$$ 값을 $$\alpha$$로 고정하고 따로 튜닝하지 않습니다.

규모를 감으로 잡기 위해 간단히 계산해 보겠습니다. GPT-3의 $$d_{model}=12{,}288$$에서 $$W_q$$ 하나는 $$12{,}288^2 \approx$$ 1억 5,100만 개 파라미터입니다. $$r=4$$인 LoRA는 $$2 \times 12{,}288 \times 4 = 98{,}304$$개만 학습하므로 약 1,536분의 1입니다.

이 설계에서 두 가지 성질이 나옵니다. 첫째, LoRA를 모든 가중치 행렬에 적용하고 $$r$$을 원래 행렬의 랭크까지 키우면 전체 파인튜닝의 표현력을 대략 회복합니다. 같은 상황에서 어댑터는 MLP로, 프리픽스 방식은 긴 입력을 받지 못하는 모델로 수렴하는 것과 대조됩니다. 둘째, 배포할 때 $$W = W_0 + BA$$를 미리 계산해 저장하면 추론 비용이 파인튜닝 모델과 정확히 같습니다. 다른 과제로 바꿀 때는 $$BA$$를 빼고 새로운 $$B'A'$$를 더하면 됩니다.

> **핵심:** 어댑터와 달리 LoRA의 추가 경로는 선형이고 병렬이어서 본 가중치에 흡수할 수 있습니다. 그래서 추론 지연이 구조적으로 0입니다.

## 구현 방식

트랜스포머의 셀프 어텐션에는 $$W_q, W_k, W_v, W_o$$ 네 행렬이 있고, MLP에는 두 행렬이 있습니다. 저자들은 단순성과 파라미터 효율을 위해 어텐션 가중치에만 LoRA를 적용하고 MLP는 고정했습니다. 대부분의 실험에서는 $$W_q$$와 $$W_v$$만 적응시킵니다. 이때 학습 파라미터 수는 $$\lvert\Theta\rvert = 2 \times \hat{L}_{LoRA} \times d_{model} \times r$$이고, $$\hat{L}_{LoRA}$$는 LoRA를 붙인 행렬의 수입니다. 멀티헤드 구조여도 $$W_q$$는 하나의 $$d_{model}\times d_{model}$$ 행렬로 다룹니다.

GPT-3 175B에서 저자들이 보고한 실용적 효과는 다음과 같습니다.

- 학습 VRAM: 고정된 파라미터의 옵티마이저 상태를 저장할 필요가 없어 1.2TB에서 350GB로 줄었습니다.
- 체크포인트: $$r=4$$로 $$W_q, W_v$$만 적응시키면 350GB에서 35MB로, 약 10,000배 작아집니다. 모델 100개를 저장할 때 약 35TB가 아니라 약 354GB면 됩니다.
- 학습 처리량: V100 한 장당 초당 토큰 수가 전체 파인튜닝의 32.5에서 LoRA의 43.1로 올라 약 25% 빨라졌습니다.

옵티마이저는 AdamW를 썼고, GPT-3 실험의 LoRA 학습률은 2.00E-04입니다. 단점도 있습니다. $$A, B$$를 $$W$$에 흡수해 지연을 없애면, $$A, B$$가 서로 다른 과제의 입력을 한 배치로 묶어 처리하기가 간단하지 않습니다. 지연이 중요하지 않은 경우에는 병합하지 않고 샘플마다 LoRA 모듈을 고르는 방식을 쓸 수 있습니다.

## 실험 결과

### 중소형 모델

GLUE에서 RoBERTa base의 LoRA(0.3M)는 평균 87.2로, 파인튜닝(125.0M)의 86.4보다 높았습니다. DeBERTa XXL에서는 LoRA(4.7M)가 91.3, 파인튜닝(1500.0M)이 91.1이었습니다. 생성 과제도 비슷합니다. GPT-2 medium의 E2E NLG Challenge BLEU는 LoRA(0.35M)가 70.4로, 같은 규모의 PreLayer(0.35M) 69.7과 파인튜닝 68.2보다 높았습니다.

### GPT-3 175B

7.1M 규모의 $$\text{Adapter}^{\text{H}}$$ 행은 표에서 뺐습니다. 저자들은 LoRA가 세 데이터셋 모두에서 파인튜닝과 같거나 더 낫다고 보고합니다. 4.7M LoRA의 WikiSQL 73.4는 파인튜닝의 73.8보다 낮지만, WikiSQL의 시드 간 변동이 ±0.5% 수준이어서 동등한 범위에 듭니다. 175B 규모에서는 학습 비용 때문에 항목마다 표준편차를 내지 않고, 과제별 대표값만 보고했습니다.

![GPT-3 175B에서 학습 파라미터 수에 따른 WikiSQL·MNLI 검증 정확도를 방법별로 그린 산점도](/assets/images/lora-low-rank-adaptation-of-large-language-models-summary-2.png)

파라미터 수를 늘릴 때 방법마다 곡선 모양이 다릅니다. LoRA는 넓은 파라미터 범위에서 상단에 평평하게 머뭅니다. 반면 프리픽스 임베딩 튜닝은 특수 토큰이 256개를 넘으면, 프리픽스 레이어 튜닝은 32개를 넘으면 성능이 크게 떨어집니다. 저자들은 특수 토큰이 많아질수록 입력 분포가 사전 학습 분포에서 멀어지기 때문이라고 추측합니다.

### 저랭크 업데이트 분석

GPT-3에서 학습 파라미터를 18M으로 고정하고 어떤 행렬에 배분할지 비교했습니다. $$W_q$$ 하나에 $$r=8$$을 몰아주면 WikiSQL이 70.4였고, $$W_q, W_v$$에 $$r=4$$씩 나누면 73.7이었습니다. 랭크를 높이기보다 더 많은 종류의 행렬을 적응시키는 편이 낫다는 뜻입니다. 랭크 실험에서는 $$W_q, W_v$$에 $$r=1$$만 써도 WikiSQL 73.4, MNLI 91.3이 나왔습니다.

![랭크 8과 랭크 64로 학습한 A 행렬의 특이벡터 부분공간 유사도를 ΔW_q와 ΔW_v에 대해 나타낸 히트맵](/assets/images/lora-low-rank-adaptation-of-large-language-models-summary-3.png)

히트맵을 보면 $$r=8$$과 $$r=64$$로 따로 학습한 행렬이 최상위 특이벡터 방향에서만 크게 겹칩니다. 1차원 부분공간의 정규화 유사도가 0.5를 넘습니다. 저자들은 나머지 방향이 학습 중 쌓인 잡음일 가능성이 크다고 보고, 이것으로 $$r=1$$이 잘 동작하는 이유를 설명합니다. 다만 이 분석은 96개 층 중 48번째 층을 중심으로 했습니다. 다른 층의 결과는 부록에 실었습니다.

$$\Delta W$$와 $$W$$의 관계도 살펴봤습니다. 48번째 층에서 $$\Delta W_q$$의 $$r=4$$ 방향으로 $$W_q$$를 투영하면 프로베니우스 노름이 0.32입니다. 무작위 방향으로 투영하면 0.02, $$W_q$$ 자신의 상위 방향으로 투영하면 21.67입니다. 즉 $$\Delta W$$는 $$W$$와 무관하지는 않지만, $$W$$의 상위 방향을 반복하지도 않습니다. 증폭 계수는 $$\lVert\Delta W_q\rVert_F = 6.91$$을 0.32로 나눈 약 21.5입니다. 저자들은 이 결과가 사전 학습 때 배웠지만 강조되지 않았던 과제 특화 특징을 LoRA가 증폭한다는 것을 시사한다고 해석합니다.

## 의의와 한계

LoRA는 학습 비용, 저장 비용, 과제 전환 비용을 한꺼번에 줄이면서 추론 지연과 입력 길이 손실 없이 파인튜닝 수준의 품질을 냅니다. 공유된 기반 모델 하나 위에서 수십 MB짜리 모듈만 바꿔 끼우면 다른 과제를 처리할 수 있어서, 대형 모델을 여러 과제에 서비스할 때 특히 쓸모가 큽니다. 프리픽스 튜닝처럼 다른 기법과 결합할 수도 있습니다. GPT-3 WikiSQL에서 LoRA+PE는 75.0으로 LoRA 단독보다 높았습니다.

한계도 분명합니다. 첫째, 실험 범위가 어텐션 가중치로 제한되어 있습니다. MLP, LayerNorm, 편향에 적용하는 경우는 후속 과제로 남겼고, 어느 행렬에 적용할지도 휴리스틱으로 정했습니다. 둘째, 작은 $$r$$이 모든 과제에서 통한다는 보장은 없습니다. 저자들도 사전 학습과 다른 언어로 된 과제라면 전체 재학습이 작은 $$r$$의 LoRA보다 나을 것이라고 직접 언급합니다. GPT-2 medium에서는 지표에 따라 최적 랭크가 4에서 16 사이였고, 모델 크기와 최적 랭크의 관계는 아직 열린 질문입니다. 셋째, 가중치를 병합해 지연을 없애는 구성에서는 서로 다른 과제의 요청을 한 배치로 처리하기 어렵습니다. 마지막으로, 저랭크성과 특징 증폭에 대한 해석은 일부 층과 두 과제에서 나온 경험적 관찰이어서 일반 원리로 확정하기에는 이릅니다.
