## TL;DR

### 이 연구를 시작하게 된 배경과 동기는 무엇입니까?
- 사전학습에서는 토큰당 성능 향상, 즉 토큰 효율이 중요합니다. 그런데 같은 데이터를 반복해 읽히면 과적합이 생깁니다.
- Muon 옵티마이저를 키우면 어텐션 로짓이 폭주합니다. 활성 9B 규모 MoE 실험에서는 최대 로짓이 1000을 넘었습니다. 기존 해법인 QK-Norm은 MLA 구조에 적용할 수 없습니다.
- 후학습에서는 에이전트가 상호작용할 실제 환경을 대규모로 구축하기 어렵습니다. 비용, 복잡성, 프라이버시, 접근성이 모두 걸림돌입니다.

### 이 연구에서 제시하는 새로운 해결 방법은 무엇입니까?
- 핵심은 MuonClip입니다. Muon에 weight decay, RMS 매칭, 헤드별 QK-Clip을 결합한 옵티마이저입니다. 업데이트가 끝난 뒤 로짓이 큰 헤드의 query/key 가중치만 재스케일합니다.
- 고품질 텍스트는 반복하는 대신 재구성(rephrasing)해 다시 학습시켜 토큰 효용을 높입니다.
- 도구, 에이전트, 과제, 궤적을 차례로 합성하는 파이프라인을 만들었습니다. RL은 검증 가능한 보상과 자기비평 루브릭 보상을 결합합니다.

### 제안된 방법은 어떻게 구현되었습니까?
- 모델은 384개 전문가 중 8개를 활성화하는 MoE이고, 어텐션 헤드는 64개입니다. 사전학습에는 15.5조 토큰을 썼습니다.
- 합성 궤적은 LLM 판정기가 루브릭으로 걸러 성공한 것만 남깁니다. 코딩 과제에는 실제 실행 샌드박스를 함께 씁니다.
- RL 인프라는 학습 엔진과 추론 엔진을 같은 워커에 올리는 공존 구조입니다. 체크포인트 엔진 덕분에 전체 파라미터를 교체하는 데 30초가 채 걸리지 않습니다.

### 이 연구의 결과가 가지는 의미는 무엇입니까?
- 도구 사용에서 Kimi-K2-Instruct는 τ²-Bench 평균 66.1을 기록해 DeepSeek-V3-0324의 48.8을 크게 앞섰습니다. ACEBench(En)에서는 76.5로 오픈소스 모델 중 가장 높지만, GPT-4.1의 80.1에는 못 미칩니다.
- 소프트웨어 엔지니어링에서는 SWE-Bench Verified 65.8, Multilingual 47.3으로 대부분의 베이스라인을 앞섭니다. 그래도 에이전틱 단일 시도 기준으로는 Claude Sonnet 4(72.7)와 Opus 4(72.5)가 여전히 앞섭니다.
- 대형 MoE 학습을 안정적으로 돌리려는 팀과 공개 가중치 기반 에이전트·코딩 모델이 필요한 사용자가 가장 큰 이득을 봅니다.

## 토큰은 아끼고 환경은 부족한 이중의 병목

대형 에이전트 모델을 만들 때 막히는 지점은 둘입니다. 사전학습에서는 고품질 데이터가 모자라고, 후학습에서는 에이전트가 상호작용할 실제 환경이 모자랍니다.

첫 번째 병목은 사전학습의 토큰 효율(token efficiency)입니다. 토큰 효율은 학습 중 소비한 토큰 하나당 얻는 성능 향상을 뜻하고, 토큰 하나가 모델 업데이트에 기여하는 학습 신호, 즉 토큰 효용을 높이면 토큰 효율도 곧바로 올라갑니다. 고품질 토큰의 공급이 한정되어 있으면 가진 토큰을 최대한 짜내야 합니다. 가장 쉬운 방법은 같은 데이터를 여러 번 보여 주는 반복인데, 반복은 과적합과 일반화 저하로 이어집니다. 데이터 쪽에서 반복 말고 다른 방법이 필요하고, 옵티마이저(optimizer) 쪽에서도 같은 토큰으로 더 많이 배우는 방법이 필요합니다.

옵티마이저 쪽 후보가 Muon입니다. 그런데 Muon은 규모를 키우면 어텐션 로짓 폭주(attention logit explosion)로 학습이 불안정해집니다. 저자들의 실험에서는 이 현상이 AdamW보다 Muon에서 더 자주 나타났습니다. 저자들이 바닐라 Muon으로 활성 파라미터 90억, 전체 파라미터 530억짜리 혼합 전문가(Mixture-of-Experts, MoE) 모델을 학습해 보니, 최대 어텐션 로짓이 빠르게 1000을 넘었습니다. 로짓이 이 정도까지 커지면 손실이 크게 튀는 loss spike가 생기고, 때로는 학습이 발산합니다.

기존 완화책으로는 이 문제를 풀기 어렵습니다.

- **logit soft-cap**: 어텐션 로짓을 직접 잘라 내지만, 잘라 내기 전 단계에서 query와 key의 내적은 여전히 과도하게 커질 수 있습니다.
- **QK-Norm**: query와 key를 정규화하는 방식입니다. 그러나 multi-head latent attention(MLA)에서는 추론 시 key 행렬이 완전히 구체화되지 않기 때문에 적용할 수 없습니다.

결국 MLA 구조를 유지하면서 Muon의 토큰 효율도 살리려면, 로짓 증가를 다른 경로로 억제하는 장치가 필요합니다.

두 번째 병목은 에이전트 능력의 학습 데이터입니다. 실제 환경은 풍부하고 진짜 상호작용 신호를 주지만, 비용, 복잡성, 프라이버시, 접근성 제약 때문에 대규모로 구축하기 어렵습니다. 예를 들어 가상의 금융 거래 에이전트를 학습시키려 한다고 해 봅시다. 실제 은행 송금 API와 실제 고객 계좌에 다중 턴 대화로 수만 번 접근하는 일은 비용으로도, 프라이버시로도 허용되기 어렵습니다. 이 때문에 저자들은 실제 도구 사용 시나리오를 시뮬레이션하는 합성 파이프라인으로 방향을 잡았고, 이 파이프라인으로 다양한 학습 예시를 수만 개 생성합니다.

두 병목은 같은 질문으로 모입니다. 한정된 진짜 데이터를 어떻게 더 효율적으로 쓰고, 부족한 부분을 어떻게 신뢰할 수 있는 합성 데이터로 채울 것인가입니다. 이 논문이 내놓은 대형 MoE 모델 Kimi K2의 설계는 이 질문에 대한 답으로 읽을 수 있습니다. 옵티마이저를 안정화하고, 사전학습 데이터를 반복하는 대신 재구성(rephrasing)하며, 에이전트 궤적(trajectory)을 대량으로 합성합니다.

## MuonClip: 헤드별 QK-Clip으로 어텐션 로짓 폭주를 사후에 누르는 옵티마이저

MuonClip은 Muon의 업데이트를 그대로 적용한 뒤, 로짓이 지나치게 커진 어텐션 헤드의 query/key 가중치만 줄여서 앞서 본 로짓 폭주 문제를 피합니다.

### Muon에서 로짓이 더 쉽게 폭주하는 구조적 이유

그 결과 업데이트 행렬의 특이값이 모두 같아지고, 유효 랭크가 full rank가 됩니다. Adam의 업데이트는 몇 개의 큰 특이값이 스펙트럼을 지배하는 저랭크 형태입니다. Muon으로 학습한 가중치가 Adam으로 학습한 가중치보다 특이값 엔트로피, 즉 유효 랭크가 더 높았습니다.

이 성질은 어텐션에서 증폭됩니다. 어텐션 로짓은 $$q_i \cdot k_j = (x_i \mathbf{W}_q)\cdot(x_j \mathbf{W}_k)$$라는 쌍선형 형태로 계산되고, 곱 $$\mathbf{W}_q \mathbf{W}_k^{\top}$$의 스펙트럼 노름은 두 행렬 노름의 곱으로 커집니다. 따라서 어느 한쪽의 특이값이 커지면 그 효과가 로짓에 누적됩니다. 특이값을 키우는 경향이 있는 Muon은 그만큼 로짓 폭주 위험이 큽니다.

### 계산 경로를 건드리지 않는 사후 재스케일

MuonClip은 Muon에 weight decay, 일관된 RMS 매칭, QK-Clip을 결합한 단일 옵티마이저입니다. 이 가운데 QK-Clip은 업데이트가 끝난 뒤 query와 key 투영 가중치를 재스케일해 로짓 증가에 상한을 둡니다. 해당 스텝의 forward/backward 계산은 바뀌지 않으며, 최대 로짓은 클리핑을 얼마나 강하게 할지 정하는 신호로만 쓰입니다. QK-Clip은 원인이 되는 가중치 자체를 줄입니다.

강도 신호는 헤드 $$h$$마다 배치 전체에서 관측된 최대 로짓입니다.

$$S_{\max}^{h}=\frac{1}{\sqrt{d}}\max_{\mathbf{X}\in B}\max_{i,j}\mathbf{Q}_{i}^{h}\mathbf{K}_{j}^{h\top}$$

$$B$$는 현재 배치, $$\mathbf{X}$$는 그 배치에 속한 시퀀스, $$\mathbf{Q}_i^h$$와 $$\mathbf{K}_j^h$$는 헤드 $$h$$에서 위치 $$i$$의 query와 위치 $$j$$의 key, $$d$$는 헤드 차원입니다. 로짓이 폭주하는 헤드는 일부뿐이므로, 저자들은 모든 헤드를 한꺼번에 줄이지 않고 헤드별 계수 $$\gamma_h=\min(1,\tau/S_{\max}^{h})$$를 둡니다. 여기서 $$\tau$$는 클리핑 임계값입니다. $$S_{\max}^{h}$$가 $$\tau$$ 이하인 헤드는 $$\gamma_h=1$$이 되어 아무 변화도 없습니다.

MLA에서는 헤드끼리 공유되지 않는 구성요소만 클리핑합니다. 헤드별 content 성분 $$q^C$$, $$k^C$$에는 각각 $$\sqrt{\gamma_h}$$를 곱해 두 성분의 곱이 $$\gamma_h$$배가 되게 하고, 헤드별 rotary query $$q^R$$에는 $$\gamma_h$$를 곱합니다. 여러 헤드가 공유하는 rotary key $$k^R$$은 건드리지 않습니다.

그 결과 다음 스텝에서 이 헤드의 최대 로짓은 대략 100 수준으로 돌아옵니다. 같은 스텝에서 $$S_{\max}^{h}$$가 60인 다른 헤드는 그대로 둡니다.

### 성능을 해치지 않고 일시적으로만 작동한 클리핑

저자들은 클리핑이 학습을 방해하지 않는지 먼저 소규모로 확인했습니다. 활성 파라미터 5억, 전체 30억짜리 MoE 두 개를 학습해 하나는 바닐라 Muon으로, 다른 하나는 $$\tau=30$$이라는 공격적인 임계값의 MuonClip으로 비교했는데, loss에 미친 영향은 거의 없었습니다. 이 결과를 근거로 저자들은 QK-Clip이 모델 성능을 떨어뜨리지 않고, MuonClip이 Muon의 최적화 특성과 loss 궤적을 유지한다고 판단했습니다.

초반에는 최대 로짓이 QK-Clip에 의해 100으로 눌려 있었지만, 학습이 진행되면서 $$\tau$$를 따로 조정하지 않아도 점차 일반적인 범위까지 내려왔습니다. 클리핑이 실제로 발동한 기간도 짧았습니다. 첫 70000 스텝 동안 어텐션 헤드의 12.7%가 한 번 이상 QK-Clip을 발동해 $$S_{\max}$$를 100으로 제한했고, 그 뒤로는 모든 헤드가 100 아래로 내려가 클리핑이 더 이상 작동하지 않았습니다. QK-Clip은 상시 개입하는 규제가 아니라, 위험한 초기 구간에서만 동작하는 안전장치로 작동했습니다.

![Kimi K2 사전학습의 스텝별 학습 손실 곡선](/assets/images/kimi-k2-open-agentic-intelligence-1.png)

이 곡선은 스무딩이나 서브샘플링 없이 스텝마다 찍은 원시 손실이고, 가독성을 위해 학습 극초반만 잘라 냈습니다. 약 15.5T 토큰에 이르는 전체 구간에서 손실이 튀는 지점 없이 꾸준히 내려갑니다.

## 384개 전문가와 64개 헤드: 희소성 스케일링 법칙에 따른 아키텍처 선택

### DeepSeek-V3를 출발점으로 바꾼 지점

K2는 DeepSeek-V3와 비슷한 설계를 따릅니다. 저자들은 사전학습 아키텍처를 설계할 때 DeepSeek-V3 기술 보고서를 핵심 선행 연구로 인용합니다. 두 모델의 차이는 아래 표로 정리됩니다.

| 항목 | DeepSeek-V3 | Kimi K2 |
| --- | --- | --- |
| 레이어 수 | 61 | 61 |
| 전체 파라미터 | 671B | 1.04T |
| 활성 파라미터 | 37B | 32.6B |
| 전체 전문가 수 | 256 | 384 |
| 토큰당 활성 전문가 | 8 | 8 |
| 공유 전문가 | 1 | 1 |
| 어텐션 헤드 | 128 | 64 |
| 밀집 레이어 수 | 3 | 1 |
| 전문가 그룹화 | 사용 | 미사용 |

조정한 축은 둘입니다. 전문가 수는 256에서 384로 늘렸고, 어텐션 헤드는 128에서 64로 줄였습니다.

### 희소성 48을 고른 근거

희소성(sparsity)은 전체 전문가 수를 활성 전문가 수로 나눈 비율입니다. K2는 384개 전문가 중 8개를 활성화하므로 희소성이 48입니다.

저자들은 Muon으로 학습하는 MoE 계열에 맞춘 희소성 스케일링 법칙을 소규모 통제 실험으로 세웠습니다. 활성 전문가 8개와 공유 전문가 1개는 고정하고, 전체 전문가 수만 바꿨습니다. 활성 파라미터가 같으면 토큰당 FLOPs도 같습니다. 이 조건에서 전체 전문가를 늘리면 학습 손실과 검증 손실이 모두 꾸준히 내려갔습니다.

![희소성 수준별 학습 FLOPs 대비 검증 손실 스케일링 곡선](/assets/images/kimi-k2-open-agentic-intelligence-2.png)

그림에서는 희소성마다 색이 다른 곡선을 같은 연산량 위치에서 위아래로 비교하면 됩니다. 희소성이 높은 곡선일수록 아래쪽에 놓입니다. 저자들은 이 차이를 연산량으로 환산했습니다. 연산 최적 희소성 스케일링 법칙에서 검증 손실 1.5에 도달하는 데 필요한 FLOPs를 기준으로 하면, 희소성 48은 희소성 8, 16, 32보다 FLOPs를 각각 1.69배, 1.39배, 1.15배 적게 씁니다.

저자들은 희소성을 높이면 성능은 좋아지지만 인프라 복잡도가 커진다고 밝히고, 성능과 비용의 균형점으로 48을 택했습니다.

> **핵심:** 희소성을 높이면 성능은 좋아지지만 인프라 복잡도가 커집니다. 전문가 수는 성능과 이 비용 사이의 절충으로 정해졌습니다.

### 헤드를 절반으로 줄인 이유

저자들은 같은 토큰 수로 학습하는 조건에서 헤드 수만 두 배로 늘려 보았습니다. 여러 연산 예산에서 검증 손실은 0.5%~1.2%만 개선됐습니다.

비용 쪽은 차이가 컸습니다. 전문가 수를 384로 고정한 상태에서 헤드를 64개에서 128개로 늘리면, 긴 시퀀스 추론의 FLOPs가 83% 증가합니다. 에이전트 작업에서는 다중 턴 대화와 도구 호출 결과가 문맥에 계속 쌓여 시퀀스가 길어지기 쉽습니다. 저자들은 손실 이득에 비해 이 추론 비용이 지나치게 크다고 보고 64개 헤드를 택했습니다.

정리하면 두 선택은 같은 원칙을 따릅니다. 전문가 수는 토큰당 연산을 늘리지 않고 손실을 낮추므로 인프라가 감당할 수 있는 선까지 늘렸습니다. 어텐션 헤드는 손실 이득은 작은데 추론 비용을 키우므로 줄였습니다.

## 반복 대신 재구성: 토큰 효용을 높이는 사전학습 데이터 합성

고품질 텍스트를 여러 번 다시 읽히는 대신 다른 표현으로 다시 써서 읽히면, 같은 원천 데이터에서 더 많은 학습 신호를 얻을 수 있습니다. 앞서 짚은 대로 토큰 효용을 단순 반복으로 높이려 하면 과적합이 따라옵니다. K2는 이 문제를 데이터 쪽에서 풀었습니다.

### 코퍼스와 K1.5 대비 바뀐 점

K2의 사전학습 코퍼스는 15.5조 토큰 규모이며, 웹 텍스트, 코드, 수학, 지식의 네 영역으로 나뉩니다. 데이터 처리 파이프라인은 대부분 Kimi K1.5의 방법론을 따릅니다. K1.5와 비교해 가장 크게 달라진 부분은 재구성(rephrasing) 기반 합성 데이터 생성입니다. 고품질 토큰의 양을 늘리되 큰 과적합은 일으키지 않도록 설계한 파이프라인입니다. 논문은 영역 특화 기법 두 가지를 소개합니다. 하나는 지식 데이터용이고, 하나는 수학 데이터용입니다.

### 지식 데이터: 스타일 다변화, 청크 단위 재작성, 충실도 검증

지식 집약적 텍스트를 학습할 때는 딜레마가 생깁니다. 1에폭만 돌리면 지식을 충분히 흡수하지 못합니다. 여러 에폭을 반복하면 수익이 점점 줄고 과적합 위험이 커집니다. 재구성 프레임워크는 세 요소로 구성됩니다.

- **스타일·관점 다변화 프롬프트**: WRAP에서 착안했습니다. 사실 관계는 유지하면서 문체와 관점이 다른 재작성을 LLM에 시킵니다.
- **청크 단위 자기회귀 생성**: 긴 문서를 한 번에 다시 쓰게 하면 LLM의 암묵적인 출력 길이 한계 때문에 정보가 빠질 수 있습니다. 그래서 문서를 조각으로 나눠 차례로 재작성한 뒤 다시 이어 붙입니다. 이 방식으로 문서 전체의 일관성을 지킵니다.
- **충실도 검증**: 재작성한 구간과 원문의 의미가 맞는지 비교합니다. 학습에 앞선 1차 품질 관리 단계입니다.

![긴 문서를 청크로 나눠 순차 재작성 후 이어 붙이는 파이프라인](/assets/images/kimi-k2-open-agentic-intelligence-3.png)

도식에서 눈여겨볼 부분은 두 갈래의 입력입니다. 각 조각을 재작성할 때 모델은 전체 원문을 문맥으로 함께 받습니다. 동시에 앞 단계에서 나온 재작성 결과도 다음 단계의 입력으로 이어받습니다. 이 구조 덕분에 조각 단위로 작업하면서도 문맥이 끊기지 않습니다.

반복과 재구성의 효과는 K2 초기 체크포인트에 세 가지 학습 전략을 적용해 SimpleQA 정확도로 비교했습니다.

| 전략 | 재구성 횟수 | 에폭 | SimpleQA 정확도 |
| --- | --- | --- | --- |
| 원본 위키 텍스트 반복 | 0 | 10 | 23.76 |
| 1회 재구성 후 반복 | 1 | 10 | 27.39 |
| 10회 재구성, 단일 패스 | 10 | 1 | 28.94 |

원본만 10에폭 반복한 경우보다, 한 번 재구성한 데이터를 같은 횟수만큼 반복한 경우의 정확도가 더 높았습니다. 반복을 아예 없애고 10가지 재작성본을 한 번씩만 본 경우가 가장 높았습니다. 저자들은 이 방법을 다른 대규모 지식 코퍼스에도 적용해 비슷한 결과를 얻었습니다. 실제 학습에서는 각 코퍼스를 최대 두 번까지만 재구성했습니다.

### 수학 데이터: 학습 노트 스타일과 번역

수학 쪽에서는 SwallowMath의 방법론을 따랐습니다. 고품질 수학 문서를 "학습 노트" 스타일로 다시 썼고, 다른 언어로 된 고품질 수학 자료를 영어로 번역해 다양성을 넓혔습니다. 저자들은 합성 데이터를 계속 확장하는 전략에 아직 풀리지 않은 과제가 있다고 밝힙니다. 다양한 원천 영역으로 일반화하면서 사실 정확성을 지키는 일, 환각과 의도치 않은 유해성을 줄이는 일, 대규모 데이터셋으로 확장하는 일입니다.

> **핵심:** 같은 사실을 다른 문장으로 여러 번 보는 쪽이, 같은 문장을 여러 번 보는 쪽보다 지식 흡수에 유리했습니다. 재구성은 에폭 수를 데이터 다양성으로 바꾸는 장치입니다.

## 작은 EP와 겹치기 중심의 사전학습 시스템 및 학습 스케줄

K2는 유연한 병렬화 조합 위에서 활성화 메모리를 재계산·FP8 저장·CPU 오프로드로 줄이고, 통신과 오프로드를 계산과 겹치도록 시스템을 짰습니다.

### 병렬화: 노드 수에 묶이지 않는 하나의 구성

학습 자원은 학습 도중에도 바뀌기 때문에, 저자들은 특정 자원량에만 맞는 전략 대신 일정 배수의 노드 수라면 어디서든 돌아가는 유연한 구성을 택했습니다. 구성은 파이프라인 병렬(PP), 전문가 병렬(EP), ZeRO-1 데이터 병렬을 결합한 것입니다. 노드가 많으면 옵티마이저 상태가 분산되어 장치당 부담이 거의 없어집니다. 노드가 적으면 일부 상태를 CPU로 내립니다. 소규모 실험과 대규모 학습이 같은 구성을 그대로 쓰기 때문에 실험 반복이 빨라집니다.

앞서 본 헤드 축소 덕분에 K2는 DeepSeek-V3보다 어텐션 연산 시간이 짧습니다. 그만큼 1F1B 단계에서 계산과 통신을 완전히 겹치려면 EP 연산 시간도 줄여야 했고, 그래서 가능한 가장 작은 EP 크기를 택했습니다. EP 그룹이 작으면 전문가 균형 제약도 느슨해져서, 추가 튜닝 없이 최적에 가까운 속도가 나옵니다.

파이프라인 스케줄은 DualPipe 대신 interleaved 1F1B입니다. DualPipe는 파라미터와 그래디언트 메모리를 두 배로 요구합니다. 이를 메우려 PP를 늘리면 버블이 생기고 EP를 늘리면 오버헤드가 커져서, 1조 파라미터 규모에서는 비용이 지나치게 컸습니다. interleaved 1F1B는 단계를 잘게 나누는 만큼 PP 통신이 늘어납니다. 저자들은 weight-gradient 계산을 각 마이크로배치의 backward에서 떼어 내 PP 통신과 병렬로 돌렸고, 그 결과 warm-up 단계를 뺀 모든 PP 통신이 겹쳐집니다.

### 활성화 메모리: 재계산, FP8 저장, CPU 오프로드

남은 GPU 메모리에 활성화를 맞추는 방법은 세 가지입니다.

- **선택적 재계산**: LayerNorm, SwiGLU, MLA up-projection, MoE down-projection을 선택적으로 재계산합니다.
- **FP8 저장**: MoE up-projection과 SwiGLU의 입력을 타일 단위, FP32 스케일의 FP8-E4M3로 압축해 저장합니다. 소규모 실험에서 손실 증가는 측정되지 않았습니다. 다만 예비 연구에서 성능 저하 위험이 관찰되어 연산 자체에는 FP8을 쓰지 않습니다.
- **CPU 오프로드**: 나머지 활성화는 모두 CPU RAM으로 보냅니다.

오프로드는 copy engine이 맡아 계산·통신 커널과 겹치게 스트리밍합니다. 1F1B 단계에서는 이전 마이크로배치의 forward 활성화를 내보내면서 다음 마이크로배치의 backward 활성화를 미리 가져옵니다. 오프로드 트래픽이 PCIe를 함께 쓰므로 혼잡으로 EP 트래픽이 영향을 받을 수 있지만, 테스트에서 EP 통신은 완전히 겹쳐진 상태를 유지했습니다.

![파이프라인 단계별로 계산·통신·오프로드가 시간축에서 겹쳐지는 스케줄 도식](/assets/images/kimi-k2-open-agentic-intelligence-4.png)

도식 아래쪽 격자는 네 개 파이프라인 스테이지의 forward·backward 마이크로배치 배치를 보여줍니다. 확대된 세 패널에서는 계산(Attn, MLP, WGrad), 통신(EP dispatch/combine, PP), 오프로드(Offload, Onload, Load)가 각각 별도 줄에서 동시에 진행됩니다. 오프로드 블록이 여러 계산 블록에 걸쳐 있어, 메모리 이동이 계산 시간 뒤에 숨는 구조가 드러납니다.

### 학습 스케줄: WSD 뒤 어닐링과 장문맥 확장

사전학습은 4,096 토큰 문맥, MuonClip, WSD 학습률 스케줄로 앞서 본 전체 코퍼스를 처리했습니다. 단계별 설정은 다음과 같습니다.

| 단계 | 토큰 수 | 시퀀스 길이 | 학습률 |
| --- | --- | --- | --- |
| 안정 구간 (500스텝 warm-up 뒤) | 10T | 4k | 2e-4 고정 |
| 감쇠 구간 | 5.5T | 4k | 2e-4 → 2e-5 cosine |
| 어닐링 + 장문맥 활성화 | 400B, 이어서 60B | 4k, 이어서 32k | 두 단계 합쳐 2e-5 → 7e-6 |

weight decay는 전 구간 0.1, 전역 배치 크기는 6,700만 토큰으로 고정했습니다. 어닐링과 장문맥 단계에서도 배치 크기는 그대로 두고 학습률만 위 표처럼 낮췄습니다. 32k까지 학습한 뒤에는 YaRN으로 문맥 창을 128k까지 늘렸습니다.

## 도구 명세에서 검증된 궤적까지: 대규모 에이전트 데이터 합성 파이프라인

K2는 시뮬레이션과 실제 환경에서 도구·에이전트·과제·궤적을 차례로 합성하고, 루브릭 판정으로 성공한 상호작용만 남겨 검증 가능한 도구 사용 시연을 대량으로 만듭니다. 앞서 본 실제 환경 구축의 어려움이 이 설계의 출발점입니다.

### SFT 안에서 에이전트 데이터의 위치

후학습의 지도 파인튜닝도 Muon으로 진행합니다. 저자들은 이전 연구에서 Muon으로 사전학습한 체크포인트가 Muon 파인튜닝에서 가장 좋은 성능을 냈다는 결론을 근거로 들고, K2를 파인튜닝할 때도 Muon을 권합니다. 일반 지시 데이터는 프롬프트 다양성을 넓히고 응답 품질을 보장한다는 두 원칙으로 만듭니다. K1.5와 도메인 전문 모델이 후보 응답을 생성하고, LLM이나 사람 판정자가 이를 걸러냅니다. 에이전트 데이터는 다단계 상호작용 추론으로 도구 사용을 가르치려고 별도 파이프라인으로 만듭니다. 이 파이프라인은 ACEBench의 데이터 합성 프레임워크에서 영감을 받았습니다. ACEBench는 나중에 평가 벤치마크로도 쓰입니다.

### 세 단계로 이루어진 합성 파이프라인

파이프라인은 도구 명세 생성, 에이전트·과제 생성, 궤적 생성의 세 단계로 나뉩니다.

**1단계: 도구 명세 저장소.** 실제 도구와 LLM이 합성한 도구를 모두 모아 대규모 명세 저장소를 만듭니다. 합성 도구는 계층적으로 늘려 갑니다. 먼저 금융 거래, 소프트웨어 앱, 로봇 제어 같은 큰 범주를 정하고, 범주마다 구체적인 응용 도메인을 여러 개 진화시킵니다. 그다음 도메인별로 인터페이스와 설명이 명확한 도구를 생성합니다. 예를 들어 가상의 금융 거래 범주 아래 "개인 뱅킹" 도메인을 두면, 그 안에 `transfer_funds(from, to, amount)`와 `get_balance(account)` 같은 도구가 생길 수 있습니다.

![실제 MCP 도구와 합성 도구의 임베딩을 t-SNE로 시각화한 두 패널 산점도](/assets/images/kimi-k2-open-agentic-intelligence-5.png)

두 패널의 군집 방식은 서로 다릅니다. 실제 MCP 도구는 원래 출처 범주에 따라 자연스럽게 뭉칩니다. 합성 도구는 미리 정한 도메인 단위로 배치되어 도구 공간을 체계적으로 덮습니다. 

**2단계: 에이전트와 과제.** 시스템 프롬프트를 다양하게 합성하고 저장소의 도구를 서로 다르게 조합해 장착하는 방식으로, 서로 다른 에이전트를 수천 개 만듭니다. 각 과제에는 명시적 루브릭이 붙습니다. 루브릭에는 성공 기준, 예상되는 도구 사용 패턴, 평가 체크포인트가 들어가며, 이를 기준으로 일관되고 객관적인 평가가 가능해집니다. 가상의 송금 과제라면 루브릭은 "송금 전에 잔액을 조회한다", "사용자에게 금액을 확인받는다", "최종 잔액이 요청과 일치한다" 같은 항목으로 구성될 것입니다.

**3단계: 궤적 생성과 필터링.** 다중 턴 상호작용은 두 시뮬레이터가 함께 만듭니다. LLM이 연기하는 사용자 페르소나가 에이전트와 대화하고, 상태를 유지하는 도구 시뮬레이터가 월드 모델처럼 도구 호출 결과를 돌려줍니다. 이렇게 생성된 궤적은 LLM 판정기가 루브릭에 비추어 평가하고, 성공 기준을 충족한 궤적만 학습 데이터로 남깁니다. 앞의 가상 예시에 적용하면, 잔액 조회 없이 바로 송금한 궤적은 판정기에서 걸러지고, 조회부터 확인과 송금까지 순서대로 마친 궤적만 SFT 데이터로 들어갑니다.

### 시뮬레이션이 닿지 않는 곳에는 실제 샌드박스

시뮬레이터가 아무리 정교해도 실제 실행을 대신하지는 못합니다. 그래서 저자들은 실행의 진정성이 중요한 코딩과 소프트웨어 엔지니어링 과제에서 시뮬레이션 환경에 실제 실행 샌드박스를 더해 함께 씁니다. 이 경우 테스트 통과율처럼 실행 결과에서 나오는 객관적 신호로 성공 여부를 판단합니다. 결과적으로 범용 도구 사용은 시뮬레이션으로 폭을 넓히고, 코드는 실제 실행으로 정확성을 확보하는 하이브리드 구조입니다.

> **핵심:** 대량 생성 뒤 루브릭으로 거르는 이 절차는 사실상 대규모 rejection sampling입니다.

저자들은 이 품질 필터링 과정이 대규모 rejection sampling을 구현한다고 설명하고, 이렇게 얻은 데이터로 SFT를 하면 도구 사용 능력이 크게 향상된다고 보고합니다. 여기서 과제마다 붙인 루브릭과 성공 기준이 판정의 기준이 됩니다. 파이프라인이 영감을 받은 ACEBench는 평가에도 쓰입니다.

## 검증 가능한 보상과 자기비평 루브릭 보상을 결합한 RL

K2의 강화학습은 정답을 기계적으로 확인할 수 있는 과제와 그렇지 않은 과제를 하나의 RL 프레임워크에서 다룹니다. 앞의 과제에는 검증기가 매기는 보상을, 뒤의 과제에는 모델이 스스로 출력을 비교해 만든 선호 보상을 씁니다. 저자들은 RL이 SFT보다 토큰 효율과 일반화가 좋다고 보고, K1.5의 RL을 이어받아 과제 다양성과 학습 FLOPs를 함께 늘렸습니다.

### 그룹 평균을 기준선으로 쓰는 목적함수

목적함수는 K1.5에서 가져왔습니다. 프롬프트 하나에 응답을 여러 개 샘플링하고, 각 응답 보상이 그룹 평균보다 얼마나 높은지에 맞춰 정책 로그 비율을 회귀시킵니다.

$$L_{\mathrm{RL}}(\theta)=\mathbb{E}_{x\sim\mathcal{D}}\left[\frac{1}{K}\sum_{i=1}^{K}\left[\left(r(x,y_{i})-\bar{r}(x)-\tau\log\frac{\pi_{\theta}(y_{i}\mid x)}{% raw %}{{\pi}_{\mathrm{old}}{% endraw %}(y_{i}|x)}\right)^{2}\right]\right]$$

각 기호의 뜻은 다음과 같습니다.

- $$x$$는 데이터셋 $$\mathcal{D}$$에서 뽑은 프롬프트이고, $$y_i$$는 같은 프롬프트에 대해 샘플링한 $$K$$개 응답 중 $$i$$번째 응답입니다.
- $$r(x,y_i)$$는 해당 응답의 보상입니다.
- $$\bar{r}(x)=\frac{1}{k}\sum_{i=1}^{k}r(x,y_{i})$$는 샘플링된 응답들의 평균 보상입니다.
- $$\pi_\theta$$는 학습 중인 정책이고, $$\pi_{\mathrm{old}}$$는 응답을 샘플링한 직전 정책입니다.
- $$\tau>0$$는 학습을 안정시키는 정규화 계수입니다.

제곱 안의 항이 0이 되면, 평균보다 보상이 높은 응답은 확률이 올라가고 낮은 응답은 내려갑니다. 이동 폭은 $$\tau$$로 나눈 만큼으로 정해지므로, $$\tau$$가 클수록 직전 정책에서 덜 멀어집니다.

예를 들어 가상의 송금 과제에서 응답 4개를 뽑았다고 하겠습니다. 이 중 잔액 조회부터 사용자 확인, 송금까지 모두 마친 응답 2개는 보상 1을, 확인 없이 송금한 응답 2개는 보상 0을 받았다면 평균은 0.5입니다. 이때 앞의 두 응답은 $$+0.5$$, 뒤의 두 응답은 $$-0.5$$라는 목표값을 향해 로그 비율이 조정됩니다. 별도 가치 함수 없이 같은 프롬프트의 형제 응답들이 기준선이 됩니다.

### 검증 가능한 보상: Gym형 환경의 확장

검증 가능한 과제는 Gym형의 확장 가능한 프레임워크에 환경으로 등록됩니다. 도메인마다 보상을 만드는 방식은 다릅니다.

- **수학·STEM·논리**: 데이터는 넓은 커버리지와 적정 난이도라는 두 원칙으로 준비합니다. 난이도는 SFT 모델의 pass@k 정확도로 재고, 중간 난이도 문제만 남깁니다.
- 모델이 실제로 따르지 않았으면서 지시를 수행했다고 주장하는 행위를 잡으려고 hack-check 층을 하나 더 둡니다.
- **소프트웨어 엔지니어링**: GitHub PR과 이슈로 환경을 만들고, Kubernetes 샌드박스가 동시 인스턴스 10,000개 이상을 안정적으로 지원합니다.

### 자기비평 루브릭 보상: 정답이 없는 과제

비교 기준은 루브릭이며, 판정하는 쪽도 학습 중인 모델 자신입니다. 비평 능력은 SFT 단계에서 미리 초기화해 둡니다. 저자들은 이 장치가 검증 가능한 영역에서 얻은 능력을 주관적 과제로 넓혀 준다고 설명합니다.

저자들은 검증 가능한 보상과 자기비평 보상을 결합해 여러 도메인의 과제가 모두 RL의 혜택을 받게 한다고 설명합니다.

### 학습을 안정시키는 세 장치

- **예산 제어**: 과제마다 최대 토큰 예산을 정해 두고, 예산을 넘긴 응답은 잘라낸 뒤 페널티를 줍니다. 모델이 제한 안에서 답을 내도록 유도해 토큰 효율을 높이려는 장치입니다.
- **PTX 보조 손실**: 엄선한 고품질 샘플을 RL 목적함수에 함께 넣어 망각을 막습니다. 저자들은 이렇게 하면 더 넓은 도메인에서 일반화가 크게 좋아진다고 보고합니다.
- **온도 감쇠**: 학습 초반에는 높은 샘플링 온도로 탐색을 넓히고, 후반에는 온도를 낮춰 안정적인 출력으로 수렴시킵니다. 탐색에서 활용으로 넘어가는 일정을 짜 둔 셈입니다.

## 학습·추론 공존 구조와 체크포인트 엔진으로 30초 미만 가중치 교체

K2의 RL 인프라는 공존 배치, 전용 체크포인트 엔진, 부분 롤아웃(partial rollout)으로 엔진 전환 시간과 롤아웃 대기를 줄입니다.

### 같은 워커를 번갈아 쓰는 공존 구조

K2의 동기식 RL은 학습 엔진과 추론 엔진을 같은 워커에 올립니다. 한 엔진이 일하는 동안 다른 엔진은 GPU 자원을 해제하거나 오프로드합니다. 반복마다 중앙 컨트롤러가 추론 엔진을 불러 새 데이터를 만들고, 학습 엔진이 그 데이터로 학습한 뒤 갱신된 파라미터를 추론 엔진에 넘깁니다. 롤아웃 동안 학습 엔진의 파라미터는 DRAM에 내려가 있어서 학습 엔진을 다시 올릴 때는 H2D 전송만 하면 됩니다. 추론 엔진 쪽이 어렵습니다. 학습 엔진과 샤딩 방식이 달라서 갱신된 파라미터를 다시 나눠 받아야 하기 때문입니다.

### 전체를 브로드캐스트하고 필요한 샤드만 가져가기

저자들은 학습 노드에 분산 체크포인트 엔진(checkpoint engine)을 함께 배치했습니다. 각 워커가 학습 엔진에서 로컬 파라미터를 받아 전체 파라미터를 모든 체크포인트 엔진 워커에 브로드캐스트하고, 추론 엔진은 그중 자기에게 필요한 샤드만 가져갑니다.

이론적으로 최적인 방식, 즉 필요한 것만 보내는 방식보다 전송량은 몇 배 많습니다. 각 추론 워커의 샤딩과 상관없이 모든 워커가 자기에게 필요 없는 샤드까지 받기 때문입니다. 저자들은 그 대가로 두 엔진을 완전히 분리해 유지보수와 테스트를 단순하게 만드는 쪽을 택했습니다. 동기화 오버헤드가 줄고 네트워크 대역폭 활용도가 올라가서, 실제로는 이 방식이 필요한 것만 보내는 방식보다 빨랐습니다. 앞서 언급한 전체 파라미터 갱신 시간도 이 방식으로 얻은 결과이며, 저자들은 이 시간이 일반적인 RL 반복에 비해 무시할 만하다고 봅니다.

### PCIe 포화로 바뀐 파이프라인

H800에서는 PCIe 포화 때문에 이론상의 3단계 파이프라인 대신 2단계 파이프라인을 썼습니다. 갱신 자체는 파라미터 단위로 나눠 파이프라인 방식으로 진행합니다. 체크포인트 엔진은 GPU마다 같은 크기의 버퍼 셋을 둡니다. 오프로드된 파라미터를 올리는 H2D 버퍼 하나와 GPU 간 브로드캐스트용 IPC 버퍼 둘이며, IPC 버퍼는 추론 엔진과 같은 물리 메모리를 공유합니다. 이론상 파이프라인은 다음 세 단계로 겹쳐 돌아갑니다.

1. 최신 가중치 샤드를 H2D 버퍼로 비동기 복사합니다.
2. 복사가 끝나면 한쪽 IPC 버퍼로 옮겨 모든 장치에 브로드캐스트합니다.
3. 추론 엔진이 다른 IPC 버퍼에서 동시에 파라미터를 재적재합니다.

H800 클러스터에서는 이렇게 돌아가지 않았습니다. H2D와 브로드캐스트를 동시에 실행하면 공유 PCIe 패브릭이 포화되고, 세 단계가 결국 순차 실행으로 무너졌습니다.

그래서 저자들은 더 단순한 2단계 방식으로 바꿨습니다. 모든 장치가 동기 H2D 전송을 한 번 하고, 그 뒤 브로드캐스트와 재적재를 병렬로 진행합니다.

이 방식은 동기 H2D 복사가 여러 번 반복되면 그만큼 느려집니다. 다만 장치 수가 많으면 모델이 작은 샤드로 쪼개져 전체 파라미터가 H2D 버퍼에 한 번에 들어가므로, 이 오버헤드가 사라진다고 저자들은 설명합니다. 저자들은 H2D, 브로드캐스트, 재적재를 겹치면 학습 엔진에서 모든 추론 엔진으로 가중치를 재분배할 때 높은 대역폭을 얻는다고 보고합니다.

### 시작과 장애 복구

대규모 학습은 장애가 잦아서 시작 시간도 중요합니다. 학습 워커는 각자 체크포인트의 일부만 읽거나 아예 읽지 않고, 필요한 파라미터를 서로 브로드캐스트합니다. 그 결과 전체 워커가 체크포인트를 디스크에서 한 번만 읽습니다. 추론 엔진도 체크포인트 엔진으로 초기화합니다. 그래서 추론 복제본 하나가 다른 복제본과 통신하지 않고도 재시작할 수 있고, 시스템이 단일 장애에 강해집니다.

### 긴 꼬리 궤적을 다음 반복으로 넘기기

다중 턴 에이전틱(agentic) 롤아웃에서는 가상 머신이나 코드 인터프리터의 응답을 기다리는 동안 GPU가 놉니다. K2는 무거운 환경을 따로 확장할 수 있는 서비스로 배포하고, 동시 롤아웃 수를 크게 늘려 비싼 상호작용의 지연을 분산합니다. 유난히 긴 궤적이 전체 롤아웃을 붙잡는 문제에는 부분 롤아웃을 씁니다. 끝나지 않은 긴 꼬리 과제는 일시 중지했다가 다음 RL 반복에서 이어서 처리합니다. 예를 들어 가상의 송금 과제에서 사용자 페르소나와의 대화가 수십 턴째 이어지는 궤적이 하나 있다고 하겠습니다. 이 궤적은 반복 경계에서 멈췄다가 다음 반복에서 재개되고, 그동안 나머지 짧은 궤적들은 이미 학습에 쓰입니다.

영어 지식 벤치마크를 보면, MMLU에서는 87.79 대 87.10으로 DeepSeek-V3-Base와의 차이가 작습니다. 반면 더 어려운 MMLU-pro에서는 69.17 대 60.59로 앞섭니다. 사실 회상형 과제인 SimpleQA에서도 35.25로 DeepSeek-V3-Base의 26.49를 크게 앞섭니다. 앞서 본 재구성 실험도 SimpleQA로 효과를 쟀습니다. 같은 지표에서 베이스 모델 간 격차가 크게 벌어진 결과는 그 실험과 방향이 같습니다.

코드와 수학에서는 격차가 더 뚜렷합니다. EvalPlus는 80.33 대 65.61, MATH는 70.22 대 61.70으로 DeepSeek-V3-Base보다 높습니다. LiveCodeBench v6는 26.29 대 24.57로 차이가 작습니다. 중국어 벤치마크인 C-Eval, CMMLU, CSimpleQA에서는 세 항목 모두 비교 모델 중 최고입니다. 

예외 가운데 하나는 GPQA-Diamond입니다. K2는 48.11로 DeepSeek-V3-Base의 50.51보다 낮습니다. "대부분의 항목에서 최고"라는 표현에서 '대부분'은 이런 예외를 포함한 말입니다. 이 표만으로 어떤 벤치마크에서든 K2 베이스가 우위라고 말할 수는 없습니다.

## 에이전틱 도구 사용과 소프트웨어 엔지니어링: 오픈소스 최고, Claude 4와는 아직 격차

후학습을 마친 Kimi-K2-Instruct는 도구 사용과 소프트웨어 엔지니어링 벤치마크에서 오픈소스 모델을 큰 폭으로 앞섭니다. Claude 4와 GPT-4.1은 일부 항목에서 여전히 K2보다 높습니다.

### 평가 설정

도구 사용은 성격이 다른 두 벤치마크로 측정했습니다. Tau2-Bench는 기존 τ-bench의 단일 제어 설정을 이중 제어 환경으로 확장한 벤치마크입니다. 에이전트와 LLM이 시뮬레이션하는 사용자가 공유 상태 위에서 각자 제한된 도구를 다룹니다. 기존 Airline·Retail 과제에 Telecom 문제 해결 도메인이 추가되었습니다. ACEBench는 영어와 중국어를 함께 다루는 API 기반 벤치마크입니다.

모든 모델은 비사고 설정(non-thinking)에서 온도 0.0으로 돌렸습니다. τ² 점수는 Airline·Retail·Telecom 세 도메인을 시드 4개로 평균한 값(Avg@4)입니다. ACEBench는 영어 전체 점수를 보고했습니다.

앞서 본 궤적 합성 파이프라인은 LLM 사용자 페르소나와 상태를 유지하는 도구 시뮬레이터로 다중 턴 상호작용을 만들었습니다. Tau2-Bench가 평가하는 상황도 같은 구조입니다. 예를 들어 금융 도메인에서 잔액 조회와 송금 도구를 가진 에이전트가 사용자와 여러 턴을 주고받으며 과제를 끝내는 경우가 여기에 해당합니다. 합성 파이프라인은 ACEBench의 데이터 합성 프레임워크에서 영감을 얻었고, 같은 벤치마크를 평가에도 썼습니다. ACEBench 점수를 읽을 때는 이 관계도 함께 고려해야 합니다.

## 확장 사고 없이 얻은 경쟁 코딩·수학·지시 따르기 성능과 Arena 오픈소스 1위

## 안전성 레드팀: 반복 탈옥에는 강하지만 Crescendo와 보안 공격에는 약점

Kimi-K2-Instruct의 안전성은 공격 전략에 따라 차이가 큽니다. Harmful 플러그인의 반복 탈옥(Iterative Jailbreak)에는 비교 모델보다 잘 버티지만, 여러 턴에 걸쳐 요청 수위를 조금씩 올리는 Crescendo에서는 Qwen3-235B-A22B·DeepSeek-R1보다 통과율이 낮습니다.

평가 방식은 다음과 같습니다. 저자들은 Promptfoo로 적대적 프롬프트를 만들었고, 유해·범죄·허위정보·프라이버시·보안 플러그인 각각을 Basic, Prompt Injection, Iterative Jailbreak, Crescendo 전략과 짝지었습니다. 조합마다 공격 프롬프트를 3개씩 생성했으며, 한 테스트 세트의 판정은 같은 검토자가 여러 차례 수동으로 검토했습니다. 아래 표의 수치는 공격을 막아낸 통과율(%)입니다.

| --- | --- | --- | --- | --- |
| Harmful Iterative Jailbreak | 92.16 | 66.67 | 72.55 | 74.51 |
| Harmful Crescendo | 64.71 | 64.71 | 80.39 | 86.27 |
| Criminal Iterative Jailbreak | 57.57 | 21.21 | 25.76 | 53.03 |

강점은 반복 탈옥에 대한 내성입니다. Harmful과 Criminal 플러그인에서 K2의 통과율은 네 모델 가운데 가장 높습니다. 저자들은 특정 평가 시나리오에 맞춘 최적화 없이 얻은 결과라고 설명합니다.

반면 Harmful 플러그인에 Crescendo 전략을 쓰면 K2의 통과율은 Qwen3-235B-A22B와 DeepSeek-R1보다 낮습니다. 보안 플러그인에서는 Iterative Jailbreak와 Crescendo 모두 Qwen3보다 크게 낮습니다. 프라이버시 플러그인의 반복 탈옥에서도 네 모델 중 가장 낮은 통과율을 보였습니다.

저자들이 직접 밝힌 한계도 있습니다. 수동 검토가 들어가므로 결과에 일정한 주관성이 남습니다. 또 API 오남용이나 외부 도구 호출을 다루는 일부 플러그인은 도구를 호출하는 에이전트 모델 평가에 더 적합합니다. 도구 사용 능력을 앞세우는 K2라면, 보안 항목의 약점은 실제 에이전트 환경에서 별도로 다시 확인해야 합니다.

## 한계와 시사점

K2에서 가져갈 것은 세 가지입니다. 로짓을 사후에 누르는 옵티마이저, 시뮬레이터로 대량 생산한 에이전트 궤적, 검증 가능한 보상과 자기비평 보상을 섞은 RL입니다. 대신 남은 약점은 토큰 과잉 생성, 시뮬레이션 충실도, 단정적 응답 편향, 클로즈드 모델과의 격차로 정리됩니다.

### 저자들이 밝힌 한계

내부 테스트에서 드러난 문제는 다음과 같습니다. 어려운 추론 과제나 정의가 불분명한 도구를 만나면 모델이 토큰을 과도하게 생성합니다. 그 결과 출력이 잘리거나 도구 호출이 불완전하게 끝나기도 합니다. 필요 없는 상황에서 도구 사용을 켜 두면 일부 과제의 성능이 떨어집니다. 소프트웨어 프로젝트 전체를 만들 때는 원샷 프롬프트보다 에이전트 코딩 프레임워크 안에서 쓸 때 성공률이 높습니다. 시뮬레이션 환경의 충실도에는 본질적인 한계가 있어서, 저자들은 코딩·SWE 과제를 실제 샌드박스로 보완했습니다. 자기비평 루브릭은 자기 한정 표현과 헤징을 금지하고 단일하고 명확한 답을 선호합니다. 이 때문에 모호한 상황에서도 확신을 과장하는 응답이 나올 수 있으며, 보정된 불확실성 처리는 향후 과제로 남겼습니다. 여기에 앞서 본 SWE-bench Verified와 ACEBench에서 Claude 4·GPT-4.1이 앞서는 결과, 그리고 보안·Crescendo 공격에 대한 약점이 더해집니다.

### 이 글의 시각: 재사용할 것과 주의할 것

이 글은 다음과 같이 판단합니다. 가장 이식성이 높은 요소는 QK-Clip입니다. forward/backward 계산은 건드리지 않고 업데이트 뒤 일부 헤드만 재스케일하며, 학습 초반에만 잠시 작동하다 꺼졌습니다. 그래서 Muon을 키워 보려는 팀에는 위험 대비 비용이 작은 안전장치로 보입니다. 다만 1T 규모 MLA 구조에서 확인한 결과이므로, 다른 어텐션 구조에서 같은 임계값이 통할지는 따로 검증해야 합니다.

합성 에이전트 데이터는 양날의 검입니다. 사용자도, 도구 시뮬레이터도, 판정기도 모두 LLM입니다. 저자들도 시뮬레이션 충실도에 본질적 한계가 있다고 인정했고, 실제 샌드박스로 보완한 범위는 코딩·SWE 과제입니다. 평가 쪽에도 겹침이 있습니다. 파이프라인이 ACEBench의 합성 프레임워크에서 영감을 받았고 같은 벤치마크로 평가했습니다. 그러니 ACEBench 점수는 실제 배포 환경보다 낙관적으로 읽는 편이 안전합니다.

단정적 응답 편향은 의료·법률·금융 상담처럼 불확실성을 정직하게 전달해야 하는 응용에서 특히 문제가 됩니다. 비사고 모드인데도 토큰이 과잉 생성되는 문제는 비용과 지연을 예측하기 어렵게 만듭니다. 앞서 본 예산 제어가 이를 완전히 막지는 못했습니다.

**쓸 만한 경우:** 오픈웨이트로 직접 호스팅해야 하고, 도구 정의가 명확한 에이전트 파이프라인을 운영하며, 에이전트 코딩 프레임워크와 함께 쓰는 경우입니다.

**피하거나 보강할 경우:** 보안 공격에 노출된 도구 에이전트, 불확실성 표현이 중요한 도메인, Claude 4 수준의 SWE 성공률이 꼭 필요한 경우입니다. 이런 경우에는 출력 길이 제한, 도구 활성화 조건 제한, 별도의 보안 레드팀을 함께 두는 것이 현실적입니다.
